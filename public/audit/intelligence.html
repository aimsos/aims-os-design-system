UCP · Intelligence — audit brief

A static, JavaScript-free copy of what the Intelligence tab shows and how much room it takes, written for review. The live prototype is a client-rendered SPA, so fetching its URL returns an empty <div id="root"> — this page exists so the section can be read without running it.

Record: Sandra Torres · VP of Operations · Meridian Corp. Measured 2026-09-11 in a 881 px content viewport.

The question being asked

Is this section too dense, and if so what should give? The measurements below say the default state does not fit one screen. What is wanted is a judgement on whether the content earns its height, and which block should yield first.

What the section is for

A rep opens a contact and decides what to do about that person now. Intelligence is a working surface, not a reading surface: work is resolved here, not just displayed. Four blocks, fixed order, nothing above the profile.

Default state — what is actually on screen

One thing is open at a time. Every collapsed block states its own weight — an exact count plus its most significant item — so it can be skipped on purpose rather than by accident.

The requirement that is not met. The spec says the default state must fit one screen without scrolling, and it does not — it overflows by 332 px at 881 px, and would still overflow a 900 px laptop. Inside the expanded row every reduction the spec sanctions is already applied: the draft is clamped to three visual lines, its expand control shares the label row, and the reason, the held card and the two action paths are all specified as never collapsing.

Levers, and what each costs

ChangeSavesCost
2 queue rows instead of 3~56 pxNone against the spec — three is a cap, not a requirement
Start the queue row collapsed~350 pxBreaks "exactly one row expanded"
Collapse Profile by default~123 pxBreaks "always visible"; a profile you must open is one nobody reads
Drop the reason paragraph from the expanded row~38 pxSpecified content for the expanded state

Only the first is free. The rest trade a stated rule for height, which is a product call rather than a layout one.

Rules the section is built to

  • No aggregate risk score on a contact. A number computed on a person is a judgement wearing a decimal point. Named signals replaced it, each with a duration and an evidence link.
  • No confidence percentage anywhere. State labels instead: Inferred / In review / Verified.
  • A suggestion is not a task. Accepting is what creates a task; accepted items show as a link out so nobody accepts the same thing twice.
  • Structural vs interpretive. Only observable, checkable claims carry Confirm. A read of tone or intent is never persisted as an attested fact about a person.
  • Inferred lives here, attested lives in Overview. Intelligence shows what the system believes; Overview shows what the organisation stands behind.
  • Nothing renders without evidence. Enforced in the data layer, not at the call site.
  • The copy test. If Sandra read her own profile she should recognise herself, not feel diagnosed. Third person, present tense, no personality framework.
